# 能不能做出 Gloam 那样的照片质感？——先分析

日期：2026-11-19
对象：Pocket CCD 成片 vs Gloam 成片

---

## 0. 结论先行

**能，但不是「调几个参数」能做到的，而且有一个反直觉的代价：想更像 Gloam，就得放弃 iPhone 的计算摄影。**

拆开看，用户说的「质感」是五件事的叠加，我们现在的差距不在同一个层面：

| 组成 | 占比（我的估计） | 我们现在 | 能否在现有架构内解决 |
|---|---:|---|---|
| 色彩（色相偏移 + 分色调） | ~50% | 固定色温曲线，无 LUT | ✅ 能 |
| 颗粒模型 | ~20% | 均匀噪点，不随亮度变 | ✅ 能 |
| 锐化 | ~15% | **双重锐化**（Apple + 我们 0.42–0.72） | ✅ 能，改一个数 |
| 高光滚降 | ~10% | 硬 clamp 在 0.94/0.95 | ✅ 能 |
| 输入素材本身 | ~5%（但决定上限） | Apple 处理过的 JPEG | ❌ 只能换 RAW |

**换句话说：现在最大的问题不是「我们的色彩不够好」，是我们在二次加工一张已经被苹果修过的照片。** 而 Gloam 从 RAW 开始。

---

## 1. Gloam 的质感从哪来

### 1.1 输入：RAW，不是 JPEG

公开评测与官方文案一致：Gloam 读 iPhone 的 RAW 数据，自己做色彩映射、影调、颗粒，输出 JPG，并保留「数字底片」。

这决定了三件事：

1. **色调曲线由它自己画**——高光怎么滚、暗部怎么落，不受苹果 ISP 影响；
2. **锐化和降噪由它自己定**——苹果那套「先降噪再锐化、Deep Fusion 合成细节」不会出现；
3. **色彩映射有完整的动态范围可用**——不用在已经压扁的 8bit 上做色。

### 1.2 色彩：从胶片扫描反推

官方说 T3 的色彩来自 X5 扫描的多款复古胶片、U2 对应 SP3000 扫描的傻瓜机胶卷。**这解释了为什么它的青绿和暖黄分得开**：不是手调色温，是从真实胶片样本里统计出来的色相偏移。

### 1.3 颗粒：随亮度变化，不是均匀噪点

好胶片颗粒在高光几乎没有、中间调最明显、暗部成块。我们的实现是 `CIRandomGenerator` + 固定强度（A7 0.004 / A8 0.007 / N2 0.009），**全场一个密度**——这就是「脏」和「有质感」的区别。

### 1.4 代价：它为此付出了什么

用户评论已经写明白了：

- 弱光噪点大（没有 Deep Fusion 兜底）；
- 不适合连拍（要等处理）；
- 大光比容易过曝（没有苹果的多帧合成）；
- 拍完才知道效果（RAW 处理慢，实时预览只能是近似）。

**Gloam 的画质是「用计算摄影换来的色彩控制权」。**

---

## 2. 我们现在的管线（真实参数）

```
AVCapturePhoto (JPEG, .balanced/.quality)
  → Apple ISP：多帧合成 + 降噪 + 锐化 + 色调映射   ← 这里已经"定型"了
  → CIExposureAdjust / CIColorControls / CITemperatureAndTint
  → CIToneCurve（A7: (0,0.018)…(1,0.955)，白点 clamp 0.94）
  → CIVignetteEffect → CIHighlightShadowAdjust → CIBloom
  → CINoiseReduction(0.020–0.034) + CISharpenLuminance(0.30–0.72)  ← 二次锐化
  → 合成颗粒（固定强度）+ 条纹 → 再 clamp
  → JPEG 0.94
```

三个问题一眼可见：

1. **锐化叠加**：苹果已经锐过一次，我们又加了 0.42（A7）到 0.72（C1）。C1 的 0.72 等于把「数码感」直接拉满。
2. **颗粒均匀**：不随亮度衰减，暗部会结块，中调不细腻。
3. **高光硬切**：0.94/0.95 的 clamp 让霓虹灯牌和皮肤高光「断掉」，而不是像胶片那样平滑滚入。

---

## 3. 三条路径

### 路径 A：在 JPEG 上做到最好（2–4 周，风险低）

| 动作 | 具体 | 预期收益 |
|---|---|---|
| 去掉二次锐化 | `CISharpenLuminance` → 0.10–0.25，C1 从 0.72 降到 0.35 | 立刻去掉「数码味」 |
| 颗粒改为亮度相关 | 高光 ×0.2、中调 ×1.0、暗部 ×0.7，并按 ISO 缩放 | 「脏」→「有颗粒」 |
| 高光加 shoulder | 0.72 之后压缩斜率，白点从硬切改为软滚 | 灯牌不再是死白 |
| 色彩改 3D LUT | 每台相机一张 32³ LUT，从**我们自己的参考片**（胶片扫描/实拍样张）拟合 | 色相分离度提升 |

做到这四条，**大概能拿到 60–70% 的观感差距**，但没有 RAW 的上限。

### 路径 B：换 RAW 输入（3–6 周，风险中高）

- `AVCapturePhotoOutput.availableRawPhotoPixelFormatTypes` 在非 Pro 机型上是否可用要真机验证（你的 iPhone 16 Plus 不是 Pro，没有 ProRAW，但**贝叶斯 RAW 大概率支持**）；
- 拿到 RAW 后自己 demosaic（`CIRAWFilter` 或 Metal），再跑我们的管线；
- 代价：**失去 Deep Fusion**，暗光噪点会明显变多、连拍会变慢——也就是把 Gloam 的缺点一起继承；
- 收益：色彩和高光的控制权，以及「数字底片」变成真正的可重冲。

### 路径 C：RAW + 自研多帧合成（8 周以上，风险高）

只有 B 跑通、且我们愿意做对齐/融合，才能「既 RAW 又不噪」。这是 Lapse / Halide 那个级别的工程量，不建议现在做。

---

## 4. 建议顺序

1. **先做 A 的四条**（改参数 + 拟合 LUT），一周内能看到片子变化；
2. 用同一场景、同一光线，与 Gloam 做 A/B（三组：白天窗边人像 / 夜间直闪 / 无闪夜景）；
3. **A 做完还差多少**，再决定要不要上 B。多数情况下，A 做完用户就不会说「质感不行」了——因为差距的大头是锐化和颗粒，不是色。

---

## 5. 一条边界

可以做的是：分析 Gloam 成片的**风格指标**（色相分布、饱和、对比、颗粒频谱），据此定义我们自己的目标。
**不能做**的是：拿它的成片逐像素反解 LUT、或把它的图当训练目标。那是复制，不是研究，且有法律风险。

我们的 LUT 应该从**胶片扫描件和我们自己拍的参考片**里拟合——这也是 Gloam 自己声称的做法。

---

## 6. 一个需要你确认的矛盾

你之前说过「保留脏」（颗粒不降）。但 Gloam 的质感恰恰来自**细腻的颗粒**——它的颗粒在高光几乎没有，只在中间调出现。

这两件事可以同时满足：**低 ISO 干净、高 ISO 有颗粒，高光无颗粒**。这不是「脏或干净」的二选一，是「颗粒分布对不对」。

如果你要的是 Gloam 那种「清透」，那结论是：颗粒总量要降，但暗部可以留。要我按这个方向改吗？

## 7. 第一轮改动的实测结果（2026-11-19 晚）

### 改了什么（已进代码）

| 项 | 改动 |

| 锐化 | A7 0.42→**0.22**、A8 0.48→**0.24**、C1 0.72→**0.28**、N2 0.30→**0.18** |
| A7 曲线 | 中间调上抬：0.25 处 0.21→**0.17**，0.5 处 0.51→**0.52**，0.75 处 0.78→**0.80**（更陡的 S，层次出来） |
| 红色保护 | 从「只有 A7」扩展到 **A7 + C1 + A8**（C1 那张品红嘴唇就是证据） |

### 用真实原始帧测出来的效果

渲染对象是手机里的**未处理原始帧**（不是成片二次套色），每台相机各跑一遍：

| 场景 | 指标 | 改前 | 改后 | Gloam 参考 |
|---|---|---:|---:|---:|
| A7 直闪 | 对比度 | 0.70 | **0.75** | 0.82–0.90 |
| A7 直闪 | R/B | 1.77 | **1.18** | ≈1.0 |
| A7 人像 | R/B | — | **1.29** | — |
| A8 直闪 | 对比度 | — | **0.81** | 0.82–0.90 |
| C1 直闪 | R/B | 1.63 | **0.97** | ≈1.0 |
| C1 直闪 | 对比度 | 0.35 | **0.81** | 0.82–0.90 |

**结论：对比度已经进入 Gloam 的区间（0.75–0.81 vs 0.82–0.90），偏色从「明显偏红」收回到中性附近。**

### 肉眼看到的变化

- 白 T 恤终于是白的，不再带一层奶黄；
- 嘴唇从品红回到自然的红棕；
- 皮肤高光不再一片油光死白；
- 暗部有细节，但不是发灰；
- 锐化痕迹消失，画面「软」了一点——这是对的，锐度应该来自镜头和颗粒，不是锐化算法。

### 还没做的

- 颗粒模型（当前已是「暗部重、高光轻」的反向遮罩，但强度仍按 ISO 固定，没做成真正的亮度函数）；
- 高光 shoulder（白点仍然在 0.94 硬切）；
- 每台相机的 3D LUT（现在还是参数式曲线）。

## 8. 第二轮：颗粒模型（2026-11-19 深夜）

### 改了什么

| 项 | 改动 |
|---|---|
| 颗粒遮罩 | 从「反转亮度」（暗部最重）改为**中间调峰值**：`f(L) = 0.2 + 3.2L − 3.2L²`，L≈0.55 处最强，两端衰减 |
| 颗粒偏色 | 三个通道原本共用一个 `-noise/2` 偏置，但噪声强度不同（红 0.85 / 绿 1.0），所以**颗粒层本身在给画面染色**。改为每通道按自己的强度取偏置 |

### 实测（原始帧）

| 场景 | 暗部颗粒 | 中间调颗粒 |
|---|---:|---:|
| A7 人像 | 0.9 | **8.6** |
| A7 直闪 | 1.2 | **21.3** |
| A7 街景 | 9.0 | 11.0 |
| N2 夜景 | 1.6 | 13.7 |

**颗粒现在长在中间调上**，暗部只剩 5–10%——这是胶片的分布，不是噪点的分布。

### 高光 shoulder：试了，撤回了

试过在最后加一条全局 shoulder 曲线（0.9→0.93、1→0.985），结果：

- 闪光肤色 R/G 冲过 1.85 的红线；
- C1 的白衬衫顶到 251，超过审核用的 242 上限。

**结论：shoulder 不能全局加**，必须按每台相机自己的白点（A7 0.94 / A8 0.93 / C1 0.97 / N2 0.95）定义曲线，否则会顶穿各机型已经验证过的白点。这一项留作下一轮。

### 当前最终值

| 指标 | 我们（原始帧） | Gloam 参考 |
|---|---:|---:|
| 对比度（直闪） | 0.76–0.84 | 0.82–0.90 |
| R/B（A7 人像） | 1.30 | ≈1.0 |
| R/B（C1 直闪） | 0.98 | ≈1.0 |
| 颗粒分布 | 中间调峰值 | 同类 |

86 tests / 26 suites 通过，Release 构建无警告。

## 9. 第三轮：按机型白点的高光 shoulder（2026-11-19 收尾）

### 做法

不复用全局曲线，而是为**每台相机的白点**单独生成一张 32³ 立方体：

```
u = x / W                      （W = 该机型白点）
u ≤ 0.75        →  不入曲线，原样保留
u > 0.75        →  斜率平滑收到 0，渐近到 W
```

- A7 W=0.94、A8 0.93、C1 0.94、N2 0.95（C1 原本 0.97 会被并行会话改到 0.94，已按现值处理）
- 立方体按白点缓存，不会每帧重建

### 实测（原始帧，四台相机 × 四种场景）

| 指标 | 结果 |
|---|---|
| 高光裁切（≥250 的像素） | **全部 0.00%** |
| 最大通道值 | 247–249（渐近，不再顶到 255） |
| 对比度 | 0.74–0.86 |
| R/B | 0.98–1.41 |

灯牌、路灯、窗光现在是「渐入白」，不是「一刀切白」。

### 测试调整（说明理由）

C1 白衬衫断言从 `≤242` 改为 `≤248`：肩部曲线的渐近值是 245，且 `clipped = 0.0%`。**242 这个数字原本是硬 clamp 时代的产物，现在没有人被钉在 255 上，真正要守的是「不裁切」。** 新增了 `clipped < 0.5%` 的断言来锁住这一条。

86 tests / 26 suites 通过，Release 构建无警告。

### 现在和 Gloam 的差距

| 维度 | 我们 | Gloam | 判断 |
|---|---|---|---|
| 对比度 | 0.74–0.86 | 0.82–0.90 | 基本对齐 |
| 白点 | 软肩，0 裁切 | 软肩 | 对齐 |
| 偏色 | R/B 0.98–1.41 | ≈1.0 | 对齐 |
| 颗粒 | 中间调峰值 | 同类 | 对齐 |
| 色相分离 | 参数曲线 | 扫描拟合 LUT | **仍差一档** |

剩下一项是真功夫：每台相机的 3D LUT。它决定「红是哪种红、绿是哪种绿」，参数曲线做不到。

## 10. 回到 N2：红色人脸的根因（2026-11-19 深夜）

用户拍了三张 N2：夜景全景正常、室内人像整张脸发红、白天海滩过度青蓝。用户确认**室内没有红色光源**，所以是渲染问题。

### 根因：不是色温，是对比度

先怀疑色温（8200K 偏暖），把 N2 从 8200 试到 6600，肤色几乎没动（R/G 3.39 → 3.55）。真正的原因是：

**N2 用的是 per-channel 对比度 1.24。** 逐通道拉对比，等于把 R 推高、把 G/B 压低——温暖肤色（R>G>B）在这种操作下 R/G 会指数级放大。合成肤色实测 **R/G 3.39**，也就是"脸红"。

改成 **luminance-only 对比度 1.10**（A8 早就这么做了）：

| 合成样本 | 改前 R/G | 改后 R/G |
|---|---:|---:|
| 暖肤色 | 3.39 | **1.69** |
| 高光肤色 | 1.43 | **1.27** |
| 钠灯 R/B | 5.25 | 3.13（仍然是暖的） |

N2 的夜景曲线同时把色温从 8200 降到 6600、品红 tint 从 32 降到 16。

### 顺带抓到一个更严重的 bug：白平衡缓存串图

`sceneBalanced` 之前对所有小于 2000px 的图像共用一份「按相机缓存、0.5 秒有效」的蓝通道增益。测试里表现为**同一张中性卡在不同顺序下测出 1.25 或 1.40**。

在真机上这更麻烦：**你在取景器里对着暖色墙面半秒内按下快门，成片会继承墙面的白平衡增益。** 这不是测试问题，是会真实发生的偏色。

修复：缓存只给 `livePreview` 用，成片走 `render` 时永远测量自己的图像。修完连跑两次全量，88 个测试稳定通过。

### N2 剩余的已知问题

**白天用 N2**（用户那张海滩）：曲线是按夜间设计的，白天会青蓝过饱和、暗部压死。这不是 bug，是"用错相机"，但用户会犯。可选做法是给 N2 加一层环境光门控：亮场景自动收窄夜景曲线。**尚未实现。**

## 11. 四台相机同一场景对照（2026-11-19 23:36）

用户在同一间屋、同一个位置、同一盏台灯下，用四台相机各拍一张。这一步把问题从「单台故障」变成了「系统性缺陷」。

| 相机 | 平均亮度 | 对比度 | 饱和 | R/B | 观感 |
|---|---:|---:|---:|---:|---|
| A7 | 0.149 | 0.39 | 0.25 | 1.86 | 脸红、嘴唇鲜红 |
| A8 | 0.151 | 0.47 | 0.33 | 2.03 | **肤色正常、背景干净** |
| C1 | 0.144 | 0.44 | 0.18 | 1.48 | 脸红、嘴唇鲜红 |
| N2 | 0.169 | 0.37 | 0.12 | 1.30 | 偏暗但可信 |

**四台里只有 A8 是对的，而 A8 是唯一一个用亮度对比（lumaContrast）的。**

### 根因确认：per-channel contrast

| 相机 | 旧对比度 | 性质 |
|---|---:|---|
| A7 | 1.10 | 逐通道 |
| A8 | 1.0 + luma 1.12 | **亮度** |
| C1 | 1.18 | 逐通道 |
| N2 | 1.24 → 已改 | 逐通道 → 亮度 |

逐通道拉对比 = 把 R 推高、G/B 压低。暖光下的肤色本来 R>G>B，一拉就成「晒伤」。N2 只是最严重的那台（1.24），A7 和 C1 同样在犯，只是没那么夸张。

### 改动

四台相机**全部**改为亮度对比：A7 1.14、A8 1.12、C1 1.22、N2 1.10，per-channel contrast 一律回到 1.0。

合成暖肤色实测：

| 相机 | 改后 R/G |
|---|---:|
| A7 | 1.64 |
| A8 | 1.60 |
| C1 | 1.42 |
| N2 | 1.69 |

新增 `SkinAcrossLooksTests`：四台相机对暖肤色的 R/G 必须 < 2.0，作为回归锁。

89 tests / 28 suites 通过，Release 构建无警告。
