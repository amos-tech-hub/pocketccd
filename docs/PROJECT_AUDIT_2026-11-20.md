## 四台相机的真实表现

11 月 20 日 16:26 室内四联样张按日期戳配色辨识相机。肤色 R/G 取同目录既有 Vision 采样 JSON。现场光、曝光与构图有差别，且样张早于最后一次 CCDLook.swift 修改。下表能描述已有真机输出，不能单独测出某个滤镜造成的增量。

| 相机 | 现有样张 | 对候选版的判断 |
|---|---|---|
| A7 · Warm 2003 | 5869，R/G 1.10。额头、眼周和脸侧呈绿灰，嘴唇仍偏红 | 高优先级。平均 R/G 低无法代表肤色健康。先隔离红色保护和阴影提升，再保住暖色与自然暗部 |
| A8 · Party Flash | 5870，R/G 1.16。肤色偏橄榄，局部颜色不均 | 高优先级。室内样张足以暴露肤色问题。实际闪光是否触发、白天黑位以及派对场景主体与环境分离仍要各自验收 |
| C1 · Cold Sharp | 5871，R/G 1.49。比同组其余照片自然，仍略偏粉 | 这组没有同等程度的坏片。11 月 19 日另一批曾记录高光裁切 8.19% 和肤色 R/G 1.84，后续改过曲线和白点。当前仍需用白衣、建筑和天空复验，保住锐度及冷调 |

湖景已有 1.0.0 与候选样张的同场景对照。实施记录用早期候选得到亮度 0.469 对 0.415、饱和度 0.476 对 0.623，回到直接滤镜链之后的 5760 为 0.447 和 0.553。它们是不同实拍，只能作为观感基线。当前预览、视频和静态照片均通过 processed，未发现现行调用使用 65³ toneCube。

## 当前源码问题

| 优先级 | 发现 | 证据与影响 |
|---|---|---|
| P1 | 四台共用的颜色处理缺少逐级对照 | CCDLook.swift:171、:759。全图白平衡、亮度对比、天空 LUT（三台）、红色保护、阴影提升和光晕依次叠加。红色保护按像素 RGB 阈值工作，不识别人脸。当前已去除把红量补到绿通道的实现，A7/A8 仍用 1.0/0.85 强度。室内花脸的具体责任阶段需同一原片逐项旁路确认 |
| P1 | 光晕未设置时，UI 和渲染的默认值来源不同 | CameraScreen.swift:2077 默认 Standard（2）。CCDLook.swift:266 读取 integer(forKey:)，缺失返回 0，而 0 是 Off，当前启动未注册该默认值。测试也需要显式覆盖 Off 与 Standard |
| P1 | 超时后的迟到拍照回调可被当成下一张 | CameraController.swift:244、:1207。多拍按 uniqueID 识别，单拍没有对应 ID 校验。迟到回调可取消下一张的 watchdog、用旧照片完成新 continuation，或改写共享 EXIF。静态路径明确，发生率未在真机测定 |
| P1 | 取景与成片的闪光和裁剪输入不同 | LivePreviewPipeline.swift:144、:186 与 CameraScreen.swift:664、:693。预览靠平均亮度预测 auto 闪光，照片靠请求与 EXIF；预览的 50 mm 缩放发生在显影后的 UI，成片先裁 50 mm 再测色和渲染。后者会改变白平衡采样、光晕和颗粒空间尺度，区别于传感器视频帧和静态照片本身的差异 |
| P1 | 试拍隔离有两处漏口 | CameraScreen.swift:837–907。导入走默认非试拍结果；试拍结果也会在打开自动保存时发起 Photos 写入，因为触发条件只有 autoSaveEnabled，结果 ID 的检查发生在写入之后。有实拍上锁相机校验的路径应和导入、自动保存共用同一策略 |
| P2 | 同一机身从其他入口得到不同显影配置 | CameraScreen.swift:744、:852 与 CCDLook.swift:632。普通单拍无卷锚点，导入及 Moment 静帧用 0.14，Moment 视频走 processed 后直接裁边，少静态照片的 lensCharacter 和末端钳位。需要写明产品预期并用同一输入验证 |
| P2 | 像素缓冲改造尚未建立真机证据 | CameraController.swift:230、:253、:1214。静态用默认 AVCapturePhotoSettings，同时请求 fileDataRepresentation，随后才尝试 pixelBuffer。当前没有证据说明支持机型常走哪个分支，也没有同一曝光的 pixelBuffer / 文件方向、镜像、颜色或时延对照 |
| P2 | 胶卷还有独立的持久化失败面 | MemoryFeatures.swift:178、:625。照片 JPEG 与两个 JSON 索引分别写入，索引失败后 append 仍返回 ID，已有重启补捞机制。延迟显影成功提示要跟踪实际写入结果，还需验证磁盘不足、索引异常和旧版备份恢复 |
| P2 | 出图、分享和双机各有独立验收边界 | CameraController.swift:581 将 Photos 输出编码为 HEIC 并回退 JPEG，胶卷仍走 JPEG。SocialSharing.swift 的单测覆盖 Instagram handoff URL。前后双摄、两机联拍、真实 IG 接收、Photos 权限、StoreKit 购买/恢复及 1.0.0 升级保留数据均须真机验证 |

## 本轮验证

- 当前主工程在 iPhone 17 Pro iOS 27.0 模拟器报告 93 tests / 28 suites，构建与测试退出成功。日志明确跳过两项真机原片用例。要求 capture.json 的目录只有 README。另有四张散装真实输入完成 16 次离线渲染，未覆盖传感器、闪光、预览会话或 Photos。
- 单一暖肤色块测试得到 A7 1.35、A8 1.34、C1 1.46、N2 1.53，门槛只检查 R/G 小于 2。它允许绿灰，也无法检查空间斑块。样张渲染用例遇到无输入、解码或渲染失败可直接跳过相应工作。
- look_acceptance.py 未给照片有效机身标签或缺少 ROI 时仍可显示 PASS，并且只枚举 JPG/JPEG/PNG。候选版 Photos 的 HEIC、缺样及每机身关键场景应显式报告覆盖情况。
- 当前 Debug 构建出现快门渲染闭包和 ExperienceViews 的 actor 隔离警告，以及 CCDLook 中两个未变更变量警告。之前的 Release 记录对应较早源码。
- 真机只读取已安装版本，没有覆盖安装、触发拍摄或对生产数据做写入。当前结论依赖现有真机样张、模拟器和静态代码路径。

## 建议的修复和放行顺序

1. 固化 1.0.0 归档与样张、待发布 Archive、当前源码之间的对应关系。给下一轮候选单独的 build 号，并记录输入照片、镜头、曝光、闪光实触发、显影设置和来源。
2. 先修光晕设置默认值、拍照 ID 与元数据绑定、试拍保存边界。修复 UI harness 后，用它跑四机切换、试拍/保存、导入、设置和胶卷流程。
3. 用同一批原片，对四台做当前渲染、红色保护旁路、光晕标准/关闭、亮度对比与阴影调整的分项渲染。保留并排图、肤色多区域及中性参考，高光/黑位按场景验收。A7/A8 优先解决花脸，N2 优先恢复夜景人脸层次，C1 先验高光与锐度。
4. 在 iPhone 16 Plus 复拍相同场景，并补第二个物理机型。覆盖室内混光人像、白衣日光、A8 直闪、N2 无闪夜景，逐个比对取景、结果页、胶卷、Photos 和分享。复核 35/50 mm、前摄镜像、转屏、自动闪光以及从 1.0.0 原地升级、购买恢复和媒介导出。归档后以待上传的同一 build 做最后确认。

### 补充发现与验收边界

- **P1 · 系统重置可能卡住连拍。** CameraController.swift:860 取消共用 captureWatchdog，却只完成单拍 continuation。系统重置时若连拍未收到足量回调，sequenceContinuation 仍可能悬挂，外层一直保留拍摄态。Moment 录制另需按请求 URL 校验回调，防止超时后的旧视频完成下一次录制。
- **P1 · 元数据未绑定到每帧。** CameraController.swift:581、:1223 在保存时取控制器的最后一份 EXIF/TIFF/GPS，连拍每张回调都会覆盖共享值，且缺失字段不会清空。多张中选择另一帧保存可能写入别张的闪光、曝光或镜头信息。位置由保存时取最近定位，关位置后仍会尝试使用来源 GPS；是否发生具体错标需要真实文件核查。
- **P1 · 无闪灯也可能套用闪光显影。** CameraController.swift:295 在设备没有闪光硬件时跳过 .on 设置，但 CameraScreen.swift:664 仍按拍摄计划把 .on 判定为已闪。前摄拍 Flash Pair/Party 时需要复核帧标签、EXIF 与实际显影。原片归档的 flashMode 是界面模式，不能代替逐帧闪光记录。
- **P1 · 双摄是第三条试拍漏口。** CameraScreen.swift:597 的 Dual Memory 也直接使用默认非试拍结果。其 MultiCam 超时任务按是否有 continuation 判定，旧计时器没有请求标识或显式取消。快速重试可能由旧计时器结束新请求。非 MultiCam 顺序拍失败时，前后摄恢复也需要覆盖。
- **P1 · 延迟显影会提前报告已存。** CameraScreen.swift:908、:954 把胶卷写入再派发到新 Task。外层可以在 JPEG 或索引写完前提示成功。非满卷、非空间不足的 JPEG 写失败没有明确反馈。原片是独立的尽力写入流程，capture.json 写失败会留下不能被原片用例识别的文件夹。
- **P2 · 配对功能的发送范围和权限需明确。** PairedCapture.swift:81 只停止发现，未断开现有连接；CameraScreen.swift:996 每次非试拍进入胶卷时都尝试把建议帧发给当前已连接设备，发送也没有与远端快门请求绑定。需要用两台真机确认关闭配对页、手动拍照、断线和失败时的实际交互。
- **P2 · 取景配置切换缺少同一时点快照。** CameraPreview.swift:39 依次更新 look、比例、闪光和卷锚点，视频线程可在更新之间读到过渡组合；LivePreviewPipeline.swift:57 和 :186 对 autoFlashActive 的访问没有共用锁。需真机记录切机、切镜头、改比例和后台恢复时旧帧是否可见。50 mm 下点击对焦还需比对屏幕触点和实际设备焦点。
- **P2 · 快门声音开关未接入。** CameraScreen.swift:33 保存用户偏好，但 :533 无条件调用播放。主快门、硬件快门和远端快门走相同 capture()。
- **P1 · 测试脚本会吞掉失败状态。** scripts/test_report.sh:21 的管道末尾使用 || true。第 32 行只查 with N skipped，当前 Xcode 日志使用逐用例 skipped 表达，脚本会漏掉这两条。建议发布判定基于测试结果及样本覆盖，运行时间只能辅助诊断。

后续放行应分别记录渲染回归、拍摄可靠性、数据与试拍边界、独立发布件验收。由同一份候选产物完成验证。当前两轮均未更改源码、工程配置或真机安装。
