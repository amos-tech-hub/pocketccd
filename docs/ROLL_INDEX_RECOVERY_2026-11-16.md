# 胶卷索引自愈（2026-11-16）

前一份文档（`ORIGINALS_AND_IDENTITY_2026-11-16.md`）补的是「产品说了但代码没做」的欠账。
这一份补的是**失败路径的欠账**：拍到的帧会因为一次索引写入失败而从产品里消失。

## 1. 问题

卷的图片和索引是两次独立写入：

1. `RollStore.add()` 先把 JPEG 写到 `Application Support/PocketRoll/`；
2. 再 `persist()` 写 `manifest.json`。

`persist()` 的返回值在 `add()` 里被丢弃。写失败（满盘、崩溃窗口、被系统挂起）时：

- 图片已在盘上，**当次会话可见**；
- 索引里没有这一帧；
- 下次启动 `load()` 只做单向过滤（索引里有、文件不在 → 丢掉），**没有反向对账**（文件在、索引没有 → 没人认领）。

结果是「看起来拍到了，第二天没了」，且全程静默。这是 24 帧一卷里最贵的一类失败：
用户不会怀疑存储，只会怀疑这一天没拍好。

## 2. 修了什么

| 机制 | 行为 |
| --- | --- |
| 启动对账 `adoptUnindexedFrames()` | 扫目录里的 `jpg/jpeg`，排除当前卷与已开发卷引用过的文件名，其余按文件创建时间收养进当前卷，并立即 `persist()` |
| 启动报告 `RollIndexHealth` | `adopted` / `missing` / `writeFailed` 三个计数，相机页 `.task` 里报一次后 `clearIndexHealth()` |
| 写失败不再静默 | `persist()` 自己维护 `writeFailed`（成功即清零），会话中途失败由 `.onChange` 单独提示 |
| 缺失不再静默 | 缺文件按文件名去重计数；同一文件可能同时被当前卷和开发卷引用 |

时序上的两个细节：

- 启动报告只看得到「启动那一刻」的状态，所以会话中途的写失败必须由 `.onChange` 兜住，两者不能共用一个提示点。
- 收养后立刻 `persist()`：否则下次启动会再收养一次（同一文件、新 UUID），卷会看起来在自己长帧。

## 3. 刻意的取舍

- **不假装机身。** 收养帧的 `cameraRawValue = "POCKET ?"`。渲染后的 JPEG 已被 `jpegData` 剥掉 EXIF，
  猜成 A7 会让接触印样的 footer 说谎。`ContactSheetRenderer` 的 cameras 行用 `CCDLook(rawValue:)`
  解析，未知值自然被丢弃，所以「?」只会出现在单帧 footer 上，不会污染整卷的机身摘要。
- **允许超过容量。** 收养可能让当前卷超过 24 张。宁可显示 26/24、下一次快门提示先开发，
  也不隐藏两帧——容量是产品的规矩，不是证据的规矩。
- **不跨境收养。** 已开发卷（archive）引用的文件不会被收养回当前卷，避免把一晚的记忆拆散。

## 4. 验收

新增 4 个单测（`Pocket Roll index`），每个都对应一条真实失败路径：

| 用例 | 证明 |
| --- | --- |
| 索引从未列出的帧在下次启动被收养 | 反向对账存在；第二次启动不重复收养 |
| 索引写失败后帧仍可恢复 | 用同名目录占住 `manifest.json` 制造写失败，重启后帧仍在 |
| 已开发卷的帧不被收养回当前卷 | 开发后的卷不会因为一次重启被拆散 |
| 文件被删后报告 missing | 缺失是可观测的，不再静默少几张 |

全量：**46 tests / 16 suites** 通过（Simulator arm64，iPhone 17 / iOS 27.2）。

构建环境备注：`xcodebuild` 在这台机器上需要脱离文件沙箱运行。Swift 宏展开会嵌套
`sandbox-exec`，被沙箱拒绝时 `swift-plugin-server` 只报
`produced malformed response`（`Observation` 宏全部失败），现象看起来像代码错误，
实际是环境限制。`-module-cache-path` 指到工作区内只能解决标准库缓存，解决不了宏。

仍待真机：

- 满盘时 `add()` 的真实失败路径（单测用的是目录占位，不是真的 ENOSPC）；
- 收养帧在卷网格里的视觉——`POCKET ?` 与空位、时间戳顺序是否符合直觉；
- 启动提示与 `RESUMED · A8 · FLASH · 1×` 同时出现时谁盖住谁（两者共用一个 toast 槽）。
