# RAW 可行性评估（2026-11-20）

问题：现在做 RAW，收益值不值？

## 1. 我们现在的输入是什么

- 拍照走 `AVCapturePhoto.pixelBuffer`（T2 改的），但那是 **ISP 处理后的 8-bit BGRA**，不是 RAW。
- 也就是说，Apple 的 Smart HDR、Deep Fusion、降噪、锐化已经全部烘进像素里，我们的 look 是在"成品"上二次调色。
- 这正是双重锐化白边、高光层次偏平、暗部被提亮的根源。

## 2. RAW 能带来什么

| 收益 | 说明 | 量级（估计） |
|---|---|---|
| 高光恢复 | RAW 是 12–14 bit 线性，没有 Apple 的 tone mapping，高光能多留 1.5–2 档 | clip 3% → <1% |
| 暗部细节 | 自己控制降噪，不必吃 ISP 的暗部提亮 | 暗部层次 +1 档 |
| 消除双重锐化 | 没有 ISP 预锐化，白边从根上消失 | 100% 裁切明显 |
| 线性域调色 | 胶片曲线可以真正做在场景线性上，而不是在 sRGB 成品上 | 观感更"物理" |
| 与 Gloam 打平 | Gloam 的质感一半来自 RAW/光谱输入 | 缩小最后 20% 差距 |

## 3. 代价

| 成本 | 说明 |
|---|---|
| 覆盖率 | ProRAW 只有 iPhone 12 Pro 以上；Bayer RAW 要自己做去马赛克、降噪、色彩矩阵 |
| 处理时间 | ProRAW 解码 + 渲染 +0.5–2 s/张；连拍会卡 |
| 存储 | 每张 20–25 MB，数字底片归档压力大 |
| 开发量 | 3–6 周：RAW 解码、色彩管理、降噪/锐化重建、测试矩阵、回退路径 |
| 定位冲突 | 默认路径是"按下就出片、马上分享"；RAW 天然慢，不能做默认 |

## 4. 收益的边界（关键）

- **社交分享**：平台会重新压缩（1080–1440 px、JPEG/WebP），RAW 多出来的高光/细节大部分被吃掉。对"发小红书/IG"的收益估计 **<20%**。
- **大屏/打印/后期**：收益明显，是专业用户场景。
- **我们的用户**：买 CCD 相机 App 的人，多数要的是"直出好看、能发"，不是"回家再调"。

## 5. 结论与建议

1. **1.0.1 不做 RAW**。当前质感短板（颗粒、黑位、高光）已经用参数补到接近 Gloam；RAW 是 3–6 周的投入，会推迟 1.0.1，且默认路径不能用。
2. 如果要做，做**Pro 模式**（单张 ProRAW，慢一点、文件大一点），不改变默认直出；可作为付费/高级功能。
3. 先做**一天的小实验**：用 ProRAW 拍 2–3 张，走现有 look 渲染，和 HEIC 版并排比高光/肤色/锐化。如果差距小于 10%，直接放弃；如果明显，再立项。

## 6. 一句话

RAW 提升的是"画质上限"，不是"分享意愿"；在 1.0.1 的时间窗口里，它是最贵、最慢、对目标帮助最小的一项。先做实验，不做默认。
